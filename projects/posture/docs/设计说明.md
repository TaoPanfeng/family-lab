# 设计说明：不是纠正身体，而是理解关系

## 1. 从需求到产品

用户的核心意图是把分散在生活里的姿势，变成**可查、可看、可调、可学、可保存**的生活工具。

因此，一个条目不只是一段百科文字，而是以下信息的组合：

`姿势 + 使用情境 + 参数化示意 + 定位步骤 + 可能帮助与局限 + 自查 + 来源 + 个人记录`

“坐”拆成电脑工位、户外长椅、安静端坐与地面坐姿；“正坐”不预先限定唯一语义；“唐僧睡”保留文化识别词，但明确属于舒适改良版。优先解决理解和实际使用，不增加账号、后台或联网依赖。

## 2. 信息与状态流

- `data.js`：不依赖 DOM 的内容数据；既能被浏览器读取，也能被 Node 测试读取。
- `core.js`：纯函数校验和计算。输入只通过白名单字段进入状态，避免外部备份夹带属性。
- `scene.js`：接收 `posture, profile, params, focus, measures`，生成同一套三维顶点。可用时交给 WebGL；不可用时进行 Canvas 软件 Z-buffer 绘制。
- `app.js`：管理当前姿势、筛选、方案、详情步骤，桥接 DOM、纯函数和场景。

```text
用户输入
  → core 边界检查
  → state 更新
  → 参数和指标更新 / scene 几何重建
  → 250 ms 防抖本地保存

保存方案
  → 独立快照（不共享可变 profile/params）
  → 本机记录 / 可导出 JSON

导入文件
  → 大小和 JSON 检查
  → 版本、条目、数值白名单验证
  → 全部合法后才合并
  → 去重 / 数量限制 / 保存
```

## 3. 三维实现与交互

人体采用椭球、圆柱和参数化关节点；家具采用立方体、曲面和简单装饰几何。尺寸以米计算，用户输入统一以 cm 表示；角度和步频另行标明单位。

WebGL 使用同一顶点数据的世界空间位置、法线和颜色属性；不加载纹理、模型文件、字体或远程资源。Canvas 备用模式有逐像素深度测试，不是把一张静态图片假装成三维。备用模式对动画性能不作高帧率承诺。

操作包括鼠标／单指拖动，滚轮缩放，双指缩放的实现，方向键与 Home，四个相机预设。部位点击选择**屏幕上最近的部位锚点**，不是三角面精确射线拾取；重叠位置可直接点击步骤按钮。

工位手臂采用简化双段几何定位；腿、躯干和睡姿接触为示意。没有完整骨骼约束、碰撞检测或关节活动范围模型。选步骤只高亮关注部位，不做动作转换动画。

## 4. 当前有意不做的内容

不做“最佳姿势”排行榜、健康评分、姿势持续越久越好、虚构穴位效果或内劲体感判断。

不凭身高算最优床垫／枕头，不计算材料受力与组织压强，不替代体态／骨科／睡眠疾病评估。

不做儿童、孕期、术后、残障人士的个体化操作建议，不模拟扶抱、移乘、跌倒恢复等高风险动作。

没有多人共享、云同步或团队后台。保存仅限当前浏览器，JSON 是跨浏览器转移方式。

## 5. 增加一个条目的方法

先在 `src/data.js` 添加对象，字段遵循已有条目风格：

```js
{
  id: 'unique-id',
  name: '条目名称',
  en: 'SCENE / POSTURE',
  category: 'sit', // all 仅用于筛选；条目使用 walk/stand/sit/lie
  scene: 'chair', // 已实现的场景类型，不能任意起名期待自动出现新模型
  badge: '使用情境',
  aliases: '搜索别名',
  brief: '一句话说明',
  principle: '使用原则',
  benefits: ['可能帮助 1', '可能帮助 2'],
  cautions: ['限制 1', '限制 2'],
  steps: [
    {title:'先检查支撑', text:'具体而不过度承诺的指导。', focus:'legs'}
    // 至少 5 个有实际意义的步骤，不能为凑数重复。
  ],
  checkpoints: ['检查点 1', '检查点 2', '检查点 3'],
  sources: ['posture'], // 必须引用 sources 已存在的键
  evidence: '一般原则改编'
}
```

已有 scene：`office, bench, chair, seiza, cross, stand, standdesk, quiet, walk, sleep`。睡姿还依赖特定 id、side 等分支；**添加全新睡姿不能只添文字**，需同步实现 `sleepScene()` 的几何、参数与步骤高亮。现有睡姿变式的参数行为不保证自动继承给任意新 id。

可用 focus：`head, torso, leftArm, rightArm, arms, legs, environment, all`。`none` 表示未选部位。来源不允许用无法核验的效果说法补足。

增加条目后要同步检查 `app.js` 的 `paramKeys()`、`renderParameters()`、`renderMetrics()`、`core.js` 的默认值与提示、对应 `scene.js` 分支，再运行构建和测试。测试中的 15 个条目等计数是当前版本契约，扩展时一起更新；不要仅删除断言掩盖功能缺口。

## 6. 数据与安全

方案仅包含用户主动保存的名称、姿势、尺寸、参数、备注和时间。渲染用户文本统一 HTML 转义，来源 URL 来自项目内置数据，不接收导入的任意 HTML 或脚本。

备份格式 `app: shenyodu-posture-lab, version: 1`。版本错误、未知姿势、越界数值拒绝整批导入；未知额外字段丢弃；原型属性不会复制。对象 ID 导入后重建，时间和内容保留；按名称、姿势、尺寸、参数、备注、创建时间共同去重。

本机服务器只提供静态文件，不接受写入；限制 HTTP 方法、真实文件根目录和目录穿越。不是生产级公网安全部署方案。

## 7. 交付方式

开发入口 `dev.html` 引用可读源码；`build.cjs` 把样式、图标、脚本内联到独立 `index.html`。源码和独立入口同时交付，不依赖构建工具下载。

零安装只指**使用已生成应用**；修改后再构建需要 Node。自动浏览器回归需要另装 Playwright，这不是运行依赖。外部资料只是链接，没有抓取并再分发机构全文。
