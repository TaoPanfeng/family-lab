# 计算方法与精度边界

## 1. 时间 → 星历 → 状态 → 渲染

`Astro.position(utcMilliseconds, experiment)` 是唯一的日月位置入口。返回日 / 月 EQD 向量（公里）、真黄赤交角、太阳 / 月球黄经、月相角、受光比例、视恒星时等。界面的显示比例、镜头、材质不作为该函数的输入。

选定的 civil 时间首先按固定 UTC 偏移转换为毫秒；改时区不重新解释已保存瞬间。未引入夏令时数据库。日期使用延伸的格里高利历；对天文计算用 UTC 近似 UT1。实际 DUT1、历史地方时、闰秒插入和远期地球自转不确定性不单独建模。1900 年日期是数学上的统一时间表示，不表示当年各地已经使用现代 UTC。

## 2. 位置数据来源

数据通过 `pyswisseph==2.10.3.2` 调用 Swiss Ephemeris 2.10.03 生成，显式使用：

```text
FLG_MOSEPH | FLG_EQUATORIAL | FLG_XYZ
```

每次返回都检查 Moshier 标记。输出是**视地心、真赤道 / 真春分点 of-date**坐标；不声称这是 JPL DE431/441，也没有随包下载或分发 Swiss/JPL 二进制表。

`calc_ut` 使用该版本自身的 ΔT 等模型，因此未来参数不会联网更新。若要使用其他星历，只需替换生成器输出，在保留坐标系 / 单位契约的前提下重新验证。

## 3. 压缩与重建

每 4 天一个分段，8 阶 Chebyshev 多项式，9 个 Gauss 采样节点。8 个通道分别为太阳 XYZ（AU）、月球 XYZ（AU）、真黄赤交角（度）、春分点方程（度）。系数是 little-endian Float32，JavaScript 通过 Clenshaw 算法以双精度求值。

数据为 18,356 个分段，5,286,528 字节；生成范围略宽于 UI 的 1900–2100，以给边界留出余量。

4,000 个固定随机种子的留出点，插值相对同一来源模型：

| 指标 | 太阳 | 月球 |
|---|---:|---:|
| 最大方向插值残差 | 0.008612″ | 0.011936″ |
| 最大距离插值残差 | 8.874 km | 0.019912 km |

**这是插值带来的额外残差，不是 Moshier 模型的总天文误差，也不是日食接触时间认证。** 生成器与报告随包，可重新运行。

## 4. 月相、四季与地球朝向

月相角为日月地心视黄经差。受光比例由月球到太阳、月球到地心两方向的点积计算，不用“每 29.5 天换一张图片”。文字月相是八分区近似标签，主要月相跳转则对真实相位角求根。

地球朝向由 Greenwich 视恒星时控制，加入星历中的春分点方程。太空视图把 EQD 转为 of-date 黄道框架，再映射到 Three.js 右手坐标。地轴按真黄赤交角倾斜；模型仅示意月球同步自转，不重建精确月面朝向和天平动。

二分二至对太阳黄经 0°、90°、180°、270°求根。天文四季分区与气象四季、二十四节气划分不混用。直射纬度以太阳赤纬近似；正午高度为 `90° − |纬度 − 赤纬|`。白昼长度使用太阳中心 −0.833° 阈值的球面解析式。没有地形、动态大气、地球极移、海洋和温度模型。

## 5. 地面观测

观测点采用 WGS84 椭球与预设海拔，地心日月向量减去观测点得到站心方向和距离。旋转为东方 / 天顶 / 北方框架，得到几何高度、方位与日月角半径。

日月圆面角半径使用 `asin(半径 / 站心距离)`；三维绘制据此投影，太阳与月球显示距离不同，但保留真实角大小。地平线可见性加上一个简化大气折射与天体角半径阈值。地平线附近的折射和局部地形会显著影响真实可见性，因此此判断不是观测保证。

事件“至少部分可见”会检查整个接触区间的 33 个时间点，不是仅看食甚。**很短的地平线边缘可见片段仍可能被粗取样漏掉。** 地形遮挡、云、雾、光污染未建模。

## 6. 食现象

### 日食

局部计算使用两个有限角半径圆面的重叠，区分全食、环食、偏食。独立计算面积遮挡比例；不是一个显示球碰到另一个显示球。

全球判定以月影轴靠近球形地球的距离、半影 / 本影半径判断。球形地表交点用于食带中心标记；WGS84 观测点仍与球形全球交点存在模型差异。不提供椭球上的精确食带多边形，不解析混合日食沿途分类。

全球食甚搜索使影轴距地心最小；地方食甚搜索使站心日月中心角距最小，因此二者不能互换。地方“最小角距”与“最大面积食分”并非在所有边缘案例中严格同一时刻，未用于专业观测安排。

### 月食

使用太阳有限半径与地球影锥，地球有效半径扩大 2% 作为简单大气近似；分类为半影 / 偏食 / 全食。这个约定会影响食既、生光等接触时刻，可能产生数分钟差异，尤其近切月食。**不应仅凭五个食甚样本相差几秒，就宣称所有接触时刻都达到秒级。**

GPU 阴影使用同一公里尺度天体参数在表面计算遮挡，但红月亮色彩、亮度是视觉近似；不同来源的阈值公式与浮点精度也会在交界瞬间产生小差异。日冕是艺术化层，不是太阳磁场或真实曝光模拟。

## 7. 两种尺度、两个世界

教学放大可以改变显示半径与距离，但不会改变星历、食接触搜索、月相或地点结果。真实地月比仅约束地球 / 月球半径和地月距离；太阳仍为方向示意。地面模式保留真实日月角大小。

假设实验把日月转到黄道坐标，缩放月球黄纬、改变黄赤交角，再转换回赤道坐标。轨道距离和黄经沿用真实数据，这是 **运动学控制变量演示，不是自洽的多体引力积分**。关闭实验后按同一日期重算真实状态。事件搜索被禁用，真实天象剧场会先恢复真实模式。

## 8. 尚未提供的专业能力

精确食带边界、混合食沿程分类、地形与月缘山谷、贝利珠、实测月面朝向、实时大气 / 极移 / DUT1、恒星星表、观测天气、古历转换、2100 年以后外推都不包含在当前版本中。

本项目适用于日地月科学教学与交互探索。计划实际观测或研究分析时，应使用权威星历、当地资料和专业工具另行确认。

## 9. V2 新增计算与显示约定

V2 沿用以上数据和误差边界，没有用界面升级冒充星历升级。

**同步视图：** 月相、日月食的两个视图使用完全相同的 UTC 毫秒时刻与地点。四季对照的 B 视图以该时刻的原始星历构造假设倾角，A 不被修改。两边虚拟镜头方向与绘制高度一致，防止把画布缩放差异误当作物理差异。窄屏依次展示，同样没有第二个独立时钟。

**正午立杆：** 按界面时区确定选定的民用日期，以所选经度的地方平太阳正午为迭代起点；用视恒星时与太阳赤经求时角，迭代 4 次趋近太阳上中天。采用该时刻赤纬计算 `α=90°−|φ−δ|`、`L=H/tan α`，忽略杆粗、地形及复杂大气。纬度 / 地形相关的高阶修正未加入，不能作为精密测量仪。极昼极夜与天顶有显式处理；可用星历端点附近会钳制迭代时间，边界样本精度不承诺。改变同一界面日期的钟点不改变这个正午样本；改变时区造成日历日期变化时，样本也会按新日期取值。

**2D 与纹理：** 兼容画面是明确标识的二维教学投影，不保留完整空间维度、月面方向或全部食影细节。正午影长示意为适应窗口可能缩放，但数值不使用图上像素反推。地球云纹、月球陨坑、日冕和地景仍是示意，不是指定日期的实际观测照片。

**安全边界：** 屏幕上展示太阳不意味着现实中可以直视太阳。软件不提供观测设备认证，也不以教学画面替代合规太阳观测防护与专业指导。
