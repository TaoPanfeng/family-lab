# 从“物理公式”到“观物”：需求与取舍

## 1. 真正要解决的问题

用户提供的公式链和水桶、高山、倒扣水银等例子，指向的不是考试刷题，而是三件事：知道现象为什么发生；看出不同现象共享的关系；让爸爸和孩子能一起动手、逐渐说清原因。

因此最小学习闭环是：

**现象问题 → 自己猜 → 只改一个条件 → 同屏比较 → 看公式如何连接 → 用自己的话记录。**

不是“讲完公式再放一个装饰动画”，也不是“先做完一套理论课才能碰实验”。默认从最具代表性的水流与落体进入，不强迫从第 1 章读到第 16 章。

## 2. 参考项目中保留什么

参考了本次上传的日月地 v1/v2 与身有度项目的结构和说明：保留离线网页、清楚的参数、面向不同理解层次的入口、对照、任务和记录的方向。

没有把三套项目生硬合并，没有直接引入它们的整套三维场景、依赖或业务逻辑。新的物理计算、实验绘图、课程文案和交互分别独立组织。成品一份 HTML，源码仍按职责拆分，兼顾“打开就能用”与“看得懂、改得动”。

## 3. 为什么公式不能强行排成唯一推导链

`v̄=Δx/Δt` 是定义；`ā=Δv/Δt` 是另一个定义；`ΣF=ma` 是需要实验支持的基本定律；`W=Fs cosθ` 是恒力做功的定义表达；能量定理需要相应条件。

因此“前一个公式自然长出后一个公式”只能作为学习结构，不能冒充逻辑证明。公式地图的箭头明确区分定义、加入定律、条件化简和类比。每个节点都有对应实验，点击后能真正操作。

## 4. 如何接住用户的水桶例子

把原始想象改为两个并列场景：左侧开放大水箱出流，右侧小球在液体外无阻力下落。两者使用同一个高度差和重力加速度，从而比较 `√(2gh)`。

质量、密度、孔直径都可以改，但各自影响的变量不同。理想速度不依赖落体质量或液体密度；孔面积进入流量，而不是直接进入理想速度。这里“调了没变”也是有价值的实验结果，界面应解释这种不变，而不是为了让滑条显得有用而制造错误效果。

再加入两个模型开关：保持水位/自然排水，理想出流/示例损失。排水时同一瞬间的实际水头不断下降；旁边的球仍从初始高度落下，不能继续宣称其末速度与任何后续出流速度相同。

## 5. 三种模式，不是三套真理

研究模式以公式与数值代入为入口；儿童模式以短问题、生活化描述为入口；亲子模式以角色分工和先猜再试为入口。

三种模式使用完全相同的参数范围和模型。儿童模式不是删掉事实，也不把所有高级内容锁死；是否继续深入，由孩子的兴趣和大人的陪伴决定。

任务的解释只能在选择猜想、按目标改一个条件之后展开。自由探索仍保留，任务按钮会将其余条件恢复到本题起点，避免给一组错误参数套上预写结论。

## 6. 一致性比功能数量重要

统一状态包含：实验、参数、对照 A、时刻、模式和记录。数值与画面都从同一个纯计算模块取得结果。模型计算不依赖帧率、随机粒子或 DOM。

每次改参数暂停并回到起点；A 固定、B 可变；对照时间按两边较长的有效时长控制。记录保存的不只是文字，还包括参数、A/B 状态和时间，恢复时保持暂停。导入前整体校验，任何记录不合法都拒绝整次导入，不静默丢弃坏记录后声称导入成功。

曲线明确是“保持其他参数不变的 61 点模型扫描”，不是播放过程中采集的真实数据。CSV 也标出模型与扫描参数。

## 7. 做了什么，以及没有假装做什么

已做 16 个教学模型、3 条关系路径、4 类学习面板、可调条件、单变量任务、A/B、播放、数值代入、曲线、PNG/CSV/JSON、发现记录、响应式界面、键盘支持和本地存储降级。

没有做真实 CFD、完整刚体引擎、大气天气系统、热传导求解、分子模拟、测量硬件连接、语音识别、云同步或在线 AI。这里的“解释”是随所选实验与条件展示的本地课程内容，不是远程生成回答。

## 8. 🪞 最值得保留的科学习惯

不是要求孩子一次猜对，而是让孩子敢于说：“我刚才猜错了，因为我只看了一个条件。”

还要追问模型本身：哪些量是定义的？哪些规律来自实验？哪些效应被忽略？如果现实结果不同，先检查条件和测量，而不是把动画当成最后裁判。
